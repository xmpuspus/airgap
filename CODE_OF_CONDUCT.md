# Code of Conduct

Airgap welcomes technical disagreement and expects respectful, specific, and
safe collaboration.

## Expected conduct

- Discuss the code, evidence, and user effect without attacking a person.
- Make room for contributors with different experience, language, and access
  needs.
- Accept correction, state uncertainty, and update a claim when evidence changes.
- Protect private data, credentials, security reports, and unpublished fixes.
- Keep reviews focused on the change and give a practical path forward.
- Stop contact when someone asks you to stop.

## Unacceptable conduct

- Harassment, threats, stalking, discrimination, or sexual attention
- Insults, intimidation, kept disruption, or deliberate misrepresentation
- Publishing private information or credentials without permission
- Pressuring a reporter to show an unfixed vulnerability publicly
- Retaliation against a reporter, contributor, or reviewer
- Using project spaces to promote unrelated products, services, or campaigns

## Scope

This policy applies in repository issues, pull requests, reviews, release notes,
project sites, and private communication about project work. It applies when
someone shows that they speak for Airgap in another public space.

## Reporting

For a public, low-risk moderation problem, tag `@xmpuspus` in the relevant GitHub
thread. For a private report, use a contact method on the
[maintainer's GitHub profile](https://github.com/xmpuspus). Do not place private
data or a security exploit in a public conduct report. Use
[GitHub's abuse reporting path](https://support.github.com/contact/report-abuse)
if the report concerns the maintainer or the maintainer cannot handle it.

For a product vulnerability, use the private path in
[`SECURITY.md`](SECURITY.md). Do not use the conduct process.

## Enforcement

The maintainer reviews available evidence, limits disclosure to people who need
it, and gives the reported person a chance to answer when safety permits. The
maintainer can edit or remove content, issue a warning, pause participation,
block an account from project spaces, or refer abuse to GitHub.

The response depends on severity, pattern, risk to others, and willingness to
correct the behavior. The maintainer records the outcome privately when the
report has sensitive information. Retaliation can lead to a stronger action.
